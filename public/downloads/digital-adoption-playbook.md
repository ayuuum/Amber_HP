# デジタル定着プレイブック（研修・役割・統治）

定着は「全員同時の一斉研修」だけでは足りません。次の3柱で90日程度を設計してください。

## 柱1：研修（学ぶ）

- [ ] 業務シナリオ別に「やることリスト」形式の教材を作った
- [ ] 座学より実機操作の時間比率を高く設定した
- [ ] 修了条件を「テスト満点」ではなく「代表タスクを1件完了」にした

## 柱2：役割（支える）

- [ ] 現場リーダー：利用促進と例外判断  
- [ ] スーパーユーザー：隣で教える・FAQ更新  
- [ ] 情シス：権限・障害・連携  
- [ ] 各ロールの週次工数目安を合意した

## 柱3：統治（続ける）

- [ ] 利用状況・問い合わせ件数・未処理バックログを定例で見る
- [ ] ルール変更（マスタ・権限・手順）は変更ログを残す
- [ ] 四半期ごとに「やめる運用」「簡略化できる手順」を見直す

## 90日ロードマップ（例）

- [ ] 0〜30日：パイロット班＋FAQ初版  
- [ ] 31〜60日：部門横展開＋スーパーユーザー育成  
- [ ] 61〜90日：定着評価と次年度改善テーマの決定  

## 最終確認

- [ ] 経営メッセージ（なぜ変えるか）を現場向けに1回以上伝えた
- [ ] 関連プレイブック記事と本シートをプロジェクトフォルダに置いた
