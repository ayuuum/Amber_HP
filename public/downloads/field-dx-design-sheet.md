# 現場DX導入前に決める5つの設計シート

導入前に「何をどう変えるか」を紙または共有ドキュメントで揃えると、後工程の手戻りが減ります。

## シート1：業務スコープ

- [ ] 対象プロセスの開始・終了条件を書いた
- [ ] 関与する部署・外部先を列挙した
- [ ] 今回「やらないこと」を明示した

## シート2：データと連携

- [ ] マスタの正（ソース・オブ・トゥルース）を決めた
- [ ] 手入力が残る項目と理由を記載した
- [ ] 既存システムとの連携方式（API／ファイル／手作業）を整理した

## シート3：権限と責任

- [ ] 参照・更新・承認のロールを定義した
- [ ] 監査ログが必要な操作を洗い出した
- [ ] 障害時のエスカレーション先を決めた

## シート4：定着と研修

- [ ] 最初の利用者（パイロット班）を指名した
- [ ] 現場向けの操作手順（1ページ）の骨子を書いた
- [ ] 定着確認の方法（ヒアリング頻度など）を決めた

## シート5：運用と改善

- [ ] 問い合わせ窓口と対応SLAの目安を決めた
- [ ] 月次で見る改善指標（利用状況・問い合わせ傾向など）を選んだ
- [ ] 次フェーズ拡大の判断会議の参加者を決めた
